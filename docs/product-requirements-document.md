## 1. 文档目的

本文档统一说明烈马自动化测试平台的产品定位、目标用户、已策划功能、当前实现状态、技术栈、实现方式、非功能要求、未完成范围和后续路线。

## 2. 产品概述

### 2.1 产品定位

烈马自动化测试平台是一套面向受控内网和私有化环境的综合测试工作台。平台将原有业务文件自动化能力、接口测试、服务器性能测试、模型配置、模型评测、报告交付、用户权限和任务基础设施整合到统一项目空间中。

平台采用“可拆分的模块化单体”路线：保留已经稳定运行的业务能力，通过 Repository、Artifact Store、任务信号队列和 Worker 边界逐步解耦，不进行推倒重写。

### 2.2 要解决的问题

1. 业务自动化依赖人工重复上传、轮询、验证和导出，执行耗时且结果难以追踪。
2. 接口资产、调试请求、场景编排和报告分散，缺少项目级版本与权限边界。
3. 服务器监控、环境体检和 CPU/GPU 满载压测容易被混为一个结论，存在误操作业务机器的风险。
4. 测试结论依赖日志或 TXT，缺少可直接交付的 DOCX/PDF 报告和不可变结果快照。
5. 模型服务只能配置和连通，尚缺少能力、翻译、性能、鲁棒性和业务专项的系统评测。
6. 多用户协作时需要项目隔离、角色权限、敏感凭据保护、审计和可恢复的后台任务。

### 2.3 产品目标

- 用统一页面完成业务自动化、接口自动化、服务器测试和报告交付。
- 所有长任务可排队、查询、停止、恢复并保留最终事实，不依赖浏览器连接存活。
- 所有业务数据按项目隔离，敏感凭据不进入任务历史、日志、报告或公开接口。
- 服务器在线监控、只读体检和满载压测明确分层，默认保护正在承载业务的设备。
- 使用内置标准集和项目自定义素材，逐步形成模型质量与性能评测闭环。
- 同时支持 PyCharm/单机应急模式和 MySQL、MinIO、Redis、独立 Worker 的正式部署模式。

### 2.4 首版非目标

- 不自动升级目标服务器的驱动、CUDA、内核、容器运行时或系统软件源。
- 不自动停止目标服务器上的业务容器或模型服务。
- 不把 `nvidia-smi` 监控、业务场景监控和 `gpu-burn` 满载压测合并成同一种结论。
- 不修改业务原始数据库；平台只使用专用数据库/schema、bucket/prefix 和 Redis 命名空间。
- 不在首版实现复杂网页内 UI 录制、桌面客户端控件自动化、RAG 全链路评测或 Agent 工具链评测。
- 不用一个“万能总分”掩盖模型能力质量、翻译质量、服务性能和资源稳定性的差异。

## 5. 核心业务流程

### 5.1 业务自动化流程

```text
登录并选择项目
  → 填写本次业务账号与测试参数
  → 选择服务器资产或手动输入目标
  → 从客户电脑选择测试目录并形成项目隔离上传快照
  → 创建持久化任务和一次性加密凭据
  → Worker 领取任务并销毁持久化凭据
  → 上传/解析/翻译/断言/摘要/AI 检查/导出
  → 持久化阶段、日志、性能样本和结果
  → 生成不可变报告快照及 DOCX/PDF
```

业务服务器与 GPU 服务器默认同机并复用 SSH；只有用户明确选择不同目标时才建立独立 GPU 连接。

### 5.2 接口自动化流程

```text
维护模块、环境、变量和接口
  → 手工创建或导入 JSON/YAML/OpenAPI/cURL
  → 保存不可变版本并按需发布
  → 在请求工作台即时调试
  → 编排多步骤场景
  → 从环境、用例或前序响应提取变量
  → 执行断言、失败停止或继续
  → 持久化结果并生成 DOCX/PDF
```

### 5.3 服务器性能流程

```text
选择/创建服务器资产
  → 建立项目归属的 SSH 长连接
  → 持续采集 CPU/GPU/内存/温度
  → 执行只读兼容性体检
  → 用户选择在线体检、CPU 或 GPU 方案
  → 繁忙与阈值安全检查
  → 执行、实时监控、协作停止
  → 保存样本、结论和独立 DOCX/PDF
```

### 5.4 模型评测目标流程

```text
选择已授权模型
  → 选择内置标准集或项目测试集不可变版本
  → 选择快速/标准/深度/自定义方案
  → 创建无凭据运行快照
  → Evaluation Worker 启动隔离 EvalScope/原生业务后端
  → 能力/Token/翻译/鲁棒/并发/业务专项评测
  → 规则评分、可选独立裁判、人工复核
  → 结果明细、对比、图表和 DOCX/PDF
```

当前该流程只完成持久化、后端隔离、Mock、停止和 Worker 骨架，尚未形成页面操作闭环。

## 6. 详细功能需求与实现方式

### 6.1 F01 登录、用户、项目与 RBAC

状态：**已实现**。

产品要求：

- 首次部署不产生默认账号或明文密码，由指定人员创建首位平台管理员和初始项目。
- 用户登录后只能访问自己有权限的项目；平台管理员可以切换全部项目。
- 写请求必须校验 CSRF；跨项目资源不可枚举。
- 支持用户启停、项目创建、成员角色、密码修改和审计查询。
- 登录失败按“客户端 IP + 规范化用户名”执行 5 分钟 5 次限制。

实现方式：

- FastAPI 中间件统一保护 `/api`、OpenAPI 和接口文档。
- 密码使用带随机盐的 scrypt 哈希；服务端会话只保存令牌哈希。
- 会话通过 HttpOnly、SameSite Cookie 维持，HTTP/HTTPS 环境显式配置 Secure 属性。
- `X-Project-ID` 传递当前项目，`X-CSRF-Token` 保护写操作。
- 改密或停用账号立即撤销该用户全部服务端会话。
- 任务、报告、上传、接口资产和 SSH 会话都保存项目归属；越权详情返回 404。

未完成：企业 SSO、LDAP/OIDC 对接、外部集中式 Secret Provider。

### 6.2 F02 运行总览与任务生命周期

状态：**已实现**。

产品要求：

- 首页展示当前任务、真实执行阶段、耗时、结果和最近执行记录。
- 排队、运行、停止、失败、完成状态必须持久化，页面刷新或服务重启后仍可查询。
- 失败任务不得显示假成功；需要重新执行时只恢复非敏感参数。

实现方式：

- SQLite/MySQL 是任务最终事实源，Redis 只发送小型唤醒信号。
- `TaskRepository`、`PlatformRepository`、`ArtifactStorage`、`TaskSignalQueue` 提供可替换边界。
- Worker 原子领取任务；Redis 不可用时退化为数据库轮询。
- 运行事件按 ID 增量读取，日志和指标前端去重，避免同一任务并发刷新。
- 心跳短暂失联先进入宽限期，恢复后清标，避免网络抖动直接误判任务中断。

未完成：跨任务统计趋势、统一跨实例租约和更细粒度运行成本分析。

### 6.3 F03 业务自动化

状态：**已实现**。

产品要求：

- 支持客户电脑目录上传、案件名称、翻译语种、业务账号、服务器目标和高级参数配置。
- 完成文件上传、解析、翻译、中文断言、摘要校验、AI 接口检查、原文/译文导出。
- 服务器直传仍从客户电脑选择文件，不允许用户填写平台容器内部路径。
- 大文件传输必须展示校验/传输进度，超时按文件大小自适应。
- 任何步骤失败时任务正确收口并保留可诊断信息。

实现方式：

- `AutomationService` 统一编排，`pipeline/` 拆分上传、解析、认证、轮询、验证、AI 检查和导出阶段。
- `integrations/` 隔离目标 HTTP API 和 SSH/SFTP 差异。
- 浏览器上传先形成项目隔离快照，服务器直传由 Worker 通过 SFTP 发送到目标服务器。
- 业务账号密码、一次性 SSH 密码和可选管理员授权进入独立加密凭据表，领取时读取并删除。
- 内网业务 API 默认不继承系统代理；只有配置明确允许时才使用代理。

未完成：把当前特定业务平台协议进一步封装成标准产品适配器，以降低目标接口变化对主流程的影响。

### 6.4 F04 实时监控

状态：**已实现**。

产品要求：

- 展示任务阶段、增量日志、CPU、GPU、内存和可信 CPU 温度。
- GPU 业务任务统计显示均值与峰值；服务器实时监控显示当前、平均和峰值。
- 翻译速度基于实际进度增量和时间戳计算，不能用总耗时简单平均。
- 日志、指标和阶段按事件增量刷新，保持用户查看位置和展开状态。

实现方式：

- 任务事件与性能样本持久化；热点同步存储调用放入线程池，避免阻塞 FastAPI 事件循环。
- CPU 温度只接受 `Package/Tctl/Tdie/Core` 或可识别的 CPU sysfs 热区，不把 high/crit 阈值和非 CPU 热区当成当前温度。
- 翻译速度按相邻进度点的有效增量计算，并识别批次重置和停滞时间。
- 原生 JavaScript 使用短轮询、事件 ID 去重和任务级刷新互斥。

未完成：基于独立实时事件通道的多 Web 实例推送，以及跨任务长期趋势。

### 6.5 F05 报告中心

状态：**已实现**。

产品要求：

- 业务自动化、接口场景和服务器性能分别生成适合本场景的阅读型报告。
- 至少支持 DOCX/PDF、执行摘要、环境、方法、结果、异常、结论和关键图表。
- 历史报告必须基于提交时的不可变快照和模板版本。
- 模型结论不可用时降级为规则结论，不阻塞报告。

实现方式：

- 报告任务持久化排队，相同运行/模板/参数使用幂等键，失败最多重试三次。
- `python-docx` 生成 DOCX，ReportLab 生成 PDF，Matplotlib 生成图表，PyPDF 用于 PDF 处理与验证。
- Linux 使用实际 Noto CJK 字体文件，PDF 在字体能力受限时使用中文 CID 字体。
- 文件记录 SHA-256；生产产物保存到 MinIO，本地模式保存到 `artifacts/`。

未完成：报告配置进一步简化、跨任务/跨报告比较和历史趋势。

### 6.6 F06 模型配置中心

状态：**已实现**。

产品要求：

- 管理模型显示名称、Base URL、模型名、API Key、启用状态和连通测试。
- 编辑时不返回已保存 Key；留空表示保留原 Key。
- 连通测试提供进行中、成功、失败和耗时反馈，不冻结页面。

实现方式：

- 模型元数据保存在平台数据库；Key 使用由 `LIEMA_MASTER_KEY` 派生的 Fernet 密钥加密。
- 公开 DTO 只返回 `has_key` 等状态，不返回明文或密文。
- 模型调用与连通测试在线程池运行。

未完成：模型对项目的授权范围、调用配额、完整调用审计和模型评测所需的协议/上下文/Tokenizer 元数据。

### 6.7 F07 接口资产与单接口调试

状态：**已实现**。

产品要求：

- 按项目维护模块、接口、环境、普通变量和加密密钥变量。
- 支持完整 HTTP(S) URL 或环境 Base URL 加相对路径。
- 支持 Query、Header、JSON、multipart、form-urlencoded 和原始文本请求体。
- 支持 JSON、YAML、OpenAPI 和 cURL 导入；cURL 粘贴只解析，不执行命令。
- 接口每次修改产生不可变版本，支持发布和历史查看。
- 调试结果展示状态码、耗时、大小、响应体、响应头和实际请求摘要。

实现方式：

- 接口模块、环境、变量、资产和版本使用项目隔离表。
- 变量通过 `{{VARIABLE_NAME}}` 递归替换；密钥变量按需解密且响应统一脱敏。
- URL 校验仅允许 HTTP(S)，拒绝嵌入账号密码、Fragment、上级路径和非 HTTP 协议。
- cURL 解析兼容常见 POSIX、Windows CMD 和 PowerShell 换行语法，拒绝 `@file`、Cookie 文件和上传文件等本地文件引用。
- 单接口调试禁止自动重定向，超时范围为 1～120 秒，响应预览上限为 2 MB。

未完成：更丰富的数据映射、Mock 服务、契约差异比较和接口历史趋势。

### 6.8 F08 接口场景自动化

状态：**已实现**。

产品要求：

- 可视化编排场景步骤、默认环境、用例参数、变量提取、断言和失败策略。
- 支持前序响应驱动后续请求，并对 URL、Query、Header、Body 和断言期望值递归替换。
- 支持单场景、批量执行、并发限制、停止、恢复、结果详情和报告。

实现方式：

- 提取来源支持 JSONPath 子集、响应头、正文正则、状态码和耗时。
- 断言覆盖等于、不等于、包含、存在、数值比较、正则和区间等 12 类；未配置断言时默认检查 HTTP 200～399。
- 单场景最多 50 个启用步骤；单批最多 20 个场景，并发度限制为 1～5。
- 提交返回 `202 queued`，Worker 原子领取；排队中可立即停止，运行中使用协作停止。
- 请求快照、响应、提取值、断言、审计和报告统一脱敏。

未完成：CSV/JSON 数据集驱动、定时执行、失败重试策略配置、跨运行趋势和基线比较。

### 6.9 F09 服务器资产、会话与兼容性体检

状态：**已实现**。

产品要求：

- 管理服务器名称、地址、SSH 用户和“只保存配置/同时保存密码”的独立策略。
- 建立持续 SSH 会话、定时采样、页面心跳、显式停止和空闲回收。
- 只读检查 OS、架构、权限、工具、磁盘、内存、容器、GPU 驱动和执行器可用性。
- 探测失败应给出“可执行、降级或阻断”结论，不应破坏基础监控连接。

实现方式：

- Paramiko 负责 SSH/SFTP；服务器密码使用平台主密钥加密，公开接口不返回密码或密文。
- 会话绑定项目，同一目标不会跨项目复用；默认空闲 5 分钟回收。
- `ServerCapabilityProbe` 执行只读命令并生成能力矩阵。
- 服务器会话当前保存在单 Web 进程，因此正式 Web 固定 `--workers 1`。

未完成：把会话和压测迁移到独立 Server Worker、跨 Web 实例租约/心跳和会话故障转移。

### 6.10 F10 CPU/GPU 监控与压测

状态：CPU 已实现；GPU 执行能力部分完成，仍有外部待验。

产品要求：

- 在线监控不依赖 `gpu-burn`；只要 `nvidia-smi` 可用就必须展示 GPU 指标。
- CPU 压测支持线程、负载、时长和温度阈值。
- GPU 压测支持逐卡选择、显存比例、繁忙保护、温度/错误安全停止。
- GPU 正在承载业务时允许只读监控，默认阻止满载压测。
- `gpu-burn -m` 只解释为显存使用比例，不承诺精确控制计算利用率。

实现方式：

- CPU 优先调用 `stress-ng`，不可用时使用 Python 降级执行器。
- GPU 指标通过 `nvidia-smi` 采集，包含使用率、显存、温度、功耗/上限、SM 频率、风扇和 P-State，并保留 available/partial/unavailable 状态。
- GPU 压测支持源码执行器和容器执行器；CUDA 11.8 作为通用镜像，CUDA 12.8 作为 Blackwell 原生镜像。
- 同一目标服务器压测串行，触发阈值后协作停止并保留已完成样本。

未完成或待验：

- 标准化 CPU 基准分数及跨机器可比口径。
- RTX 5090、RTX A6000、RTX PRO 6000 Blackwell 等更多型号实机矩阵。
- 在明确维护窗口和目标卡释放后完成 GPU 正式满载验收。

## 7. 技术方案

### 7.1 总体架构

```text
浏览器（原生 HTML/CSS/JavaScript）
        │ 登录会话 + CSRF + X-Project-ID
        v
FastAPI Web / API（单 Web 进程）
        │
        ├── Core / Pipeline / Monitoring / Reporting
        ├── Platform Repository ─────> SQLite 或 MySQL（最终事实源）
        ├── Artifact Storage ────────> 本地目录或 MinIO（大文件与报告）
```

| 数据类型 | 正式存储 | 本地/应急 | 约束 |

### 7.5 部署方案

- 本地/PyCharm：`python web_main.py`，可使用 SQLite、本地 Artifact Store、`local + embedded`，不要求 Redis。
- 正式环境：单 Web 进程 + 独立 Worker，复用平台专用 MySQL、MinIO、Redis，使用 `deploy/compose.external.yml`。
- 完全离线：在受控有网环境准备依赖和 SHA-256 清单，正式环境使用 `--network=none` 构建。
- Web 当前固定单进程，因为 SSH 会话和服务器压测仍在 Web 进程内；完成 Server Worker 后再支持多实例。
- 用户通过 PyCharm 启动服务，自动化开发过程不得擅自占用本机 8080 端口。

## 8. 非功能需求

### 8.1 安全

- 文档、代码、日志、任务快照、审计和报告不得新增明文密码、Token、SSH 密钥或数据库密钥。
- 生产 `LIEMA_MASTER_KEY` 必须由环境变量或企业密钥系统提供，并在升级/恢复前后保持一致。
- MySQL、MinIO、Redis 必须使用平台专用隔离空间，不得操作业务原始数据库。
- 接口调试和模型评测只允许受控 HTTP(S) 目标；导入内容按数据处理，不执行脚本或命令。
- 高负载测试必须显示目标、参数、预计请求量/时长和停止阈值；不得自动停止业务服务。

### 8.2 可靠性

- 任务提交成功后必须先持久化，再发送队列信号。
- Redis 不可用时任务不能丢失，Worker 应退化为数据库轮询。
- 报告和评分应支持独立重试；不可恢复的运行态必须收口为明确终态。
- 产物记录 SHA-256；正式升级前完成数据库、对象存储和持久卷备份。

### 8.3 性能与体验

- 登录首屏只加载运行和报告等当前视图所需数据，其他模块进入时懒加载。
- 同步数据库、SSH 和模型请求不得阻塞 FastAPI 事件循环。
- 桌面以 1920×1080 为主要可读性基线，并兼容 1280×720；不得出现无意义横向滚动和遮挡。
- 页面优先显示业务名称、状态、图表和可读结论，内部 ID 和原始 JSON 放入详情。

### 8.4 兼容性

- 本地支持 Windows/PyCharm；正式运行支持 Linux 容器。
- 已验证 openEuler 24.03 / 8×RTX 3090 和 CentOS 7 / 4×RTX 4090 的监控能力。
- GPU 不支持某个增强字段时显示 N/A 或 partial，不使用 0 冒充采集结果。
- SQLite/本地文件保留为单机应急方案，MySQL/MinIO 用于正式环境。

### 8.5 可维护性

- 新能力优先落入现有模块边界，不在根目录平铺业务代码。
- 目标协议、存储、队列、评测引擎和报告通过稳定契约隔离。
- 任何目录、源码分层、启动入口或部署文件变化必须同步更新 `PROJECT_STRUCTURE.md` 并运行结构回归。
- 每次实质改动同步更新 `PROJECT_PLAN.md` 的日期、进度、当前工作和测试数量。

| 正式 Redis 当前临时免密 | 长期运行安全不达标 | 独立命名空间只是过渡，P0 切换 ACL/密码 |
| 服务器会话仍在 Web 进程 | 无法安全水平扩展 Web | 固定单进程，后续迁移 Server Worker 和租约 |
| GPU 型号、驱动和负载状态差异大 | 执行器可能降级或无法形成容量结论 | 监控与压测解耦，显示采集状态，扩大实机矩阵 |
| 满载测试可能影响业务 | 存在服务退化风险 | 繁忙保护、维护窗口、明确目标卡、阈值自动停止 |
| 模型 Benchmark 许可证各异 | 数据集无法随意分发 | 逐数据集核许可证、锁版本和 SHA-256，正式环境离线加载 |
| 模型评测依赖较重 | 与主项目依赖冲突、拖慢 Web | 固定 EvalScope 版本、隔离 Python 子进程/独立 Worker |
| 裁判模型存在偏差 | 开放题评分不稳定 | 独立裁判、盲评、锚点校准、规则不可覆盖、人工复核 |
| UI 自动化选择器不稳定 | 脚本维护成本高 | 首期脚本导入和受控编辑，不承诺万能自愈 |
| 备份仍在同一故障域 | 主机级故障时无法恢复 | 建立离机/异地副本和周期恢复演练 |

## 11. 验收原则

### 11.1 通用验收

- 所有新增能力必须经过项目权限、跨项目隔离、凭据脱敏和审计检查。
- 长任务必须具备排队、运行、停止、失败和完成终态，异常不能永久停留在运行中。
- Redis、可选模型或可选工具不可用时，必须给出明确降级结论，不得伪造成功或 0 值。
- DOCX/PDF 报告需要检查结构、中文字体、图表、分页、裁切和文件签名。
- 代码改动必须通过相关定向测试，并保持既有业务自动化、接口、服务器性能和报告能力无回归。

### 11.2 当前已知验收基线

- 自动化回归：240 项全部通过，另有 49 项子测试通过。
- 正式 Web/Worker、MySQL、MinIO、Redis 心跳和局域网健康检查已通过。
- 平台专用 MySQL、MinIO 和 5 个持久卷已完成同机隔离恢复演练。
- 固定镜像前滚、回滚和再次前滚已完成。
- openEuler 24.03 / 8×RTX 3090、CentOS 7 / 4×RTX 4090 已完成监控与兼容性验证；满载结论受业务负载和维护窗口限制。
- EvalScope 1.11.1 的标准评测、WMT 和 `perf` 已在隔离 PoC 中跑通；模型评测基础页面与 Mock 运行闭环已交付，第一台真实模型联调仍为外部待验。
