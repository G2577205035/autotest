# 烈马自动化测试平台交付与验收说明

> 文档版本：1.3  
> 基线日期：2026-08-28  
> 适用版本：`auto-test 2.0.0`  
> 当前结论：本地/PyCharm 核心功能与正式服务器 Web/Worker 部署均可验收；平台专用 MySQL、MinIO、持久卷的同机隔离恢复及镜像回滚已通过。长期运行仍需补齐 Redis ACL/密码认证、离机备份副本和部分 GPU 实机矩阵。

## 1. 交付范围

本次交付采用“可拆分的模块化单体”架构，保留现有业务自动化能力，并完成以下平台能力：

- 业务自动化：上传、解析、翻译、断言、摘要、AI 检查、导出、实时日志和性能监控。
- 企业报告：不可变快照、六章模板、图表、规则/模型结论、DOCX/PDF 生成与下载。
- 接口中心：模块、接口、环境、普通变量、加密变量、导入、版本、发布和单接口调试。
- 接口自动化：场景编排、变量提取、12 类断言、批量执行、持久化队列和 DOCX/PDF 报告。
- 服务器性能：服务器资产、加密凭据、SSH 长连接、实时指标、CPU/GPU 压测、安全保护和独立报告。
- 用户与权限：首次管理员初始化、登录会话、CSRF、平台/项目角色、项目隔离和审计记录。
- 任务基础设施：SQLite/MySQL、Local/MinIO、Local/Redis 信号队列、独立 Worker 与健康检查。

UI 自动化、企业 SSO、外部 Secret Provider、独立 Server Worker、跨任务趋势和更丰富的数据集驱动不在本次交付完成范围内。

## 3. 推荐部署拓扑

```text
用户浏览器
    │ 受控局域网 HTTP，或 HTTPS
网络访问控制 / 可选反向代理
    │
Web（单进程） ───── MySQL（平台专用库）
    │              MinIO（平台专用 bucket/prefix）
    ├──── Redis（只存唤醒信号与短期心跳）
    │         │
    │       Worker（业务自动化、接口场景、企业报告）
    │
    └──── SSH / HTTP ─── 由用户明确选择的目标服务器
```

当前 Web 必须保持单进程，因为 SSH 长连接和服务器压测会话仍由 Web 进程持有。业务服务器与 GPU 服务器默认同机，只有用户明确配置不同地址时才拆分。

验收要求：

1. 未登录访问业务 API 返回 401；`/health` 和登录入口可匿名访问。
2. 写请求缺少或使用错误 CSRF 令牌时被拒绝。
3. 普通用户不能切换到未授权项目。
4. 跨项目任务、报告、上传和 SSH 会话不可见，越权资源按 404 处理。
5. 密码、Token、SSH 密钥、模型 Key 和加密密文不出现在列表、详情、日志或审计内容中。
6. 修改密码或停用账号后，原服务端会话立即失效。
7. 登录失败按“客户端 IP + 规范化用户名”执行 5 分钟 5 次限流。

## 5. 功能验收清单

### 5.1 基础与登录

- [ ] `/health` 返回 HTTP 200，且 `status=ok`。
- [ ] 首次部署不生成默认账号或明文密码，可由指定人员创建首位平台管理员和初始项目。
- [ ] 后续可使用账号密码登录、退出并切换已授权项目。
- [ ] 登录、初始化和认证状态响应带 `Cache-Control: no-store`。

### 5.2 业务自动化

- [ ] 可在页面填写本次业务账号、选择服务器资产或手动授权，并上传测试数据。
- [ ] 排队任务由独立 Worker 领取；Redis 暂时不可用时可退化为数据库轮询，不丢任务最终状态。
- [ ] 页面可查看阶段、日志、CPU/GPU/内存指标、可信 CPU 温度和翻译平均速度。
- [ ] 任务失败时正确收口，不显示假成功；一次性凭据在领取、取消或结束后清理。

### 5.3 报告中心

- [ ] 可从已完成任务创建企业报告。
- [ ] DOCX、PDF 均可下载并正常打开。
- [ ] 报告包含摘要、环境、方法、用例、结果、异常和结论；历史报告使用提交时的不可变快照。
- [ ] 模型不可用时报告降级为规则结论，不阻断生成。

### 5.4 接口中心与场景自动化

- [ ] 可创建模块、环境、普通变量和加密变量；加密变量不回显。
- [ ] 可通过 JSON/YAML/OpenAPI/cURL 导入接口，并保留不可变版本。
- [ ] 单接口调试支持 Query、Header、JSON、multipart、表单和原始文本请求体。
- [ ] 场景步骤可串联、提取变量并执行断言；批量任务和报告按项目隔离。

### 5.5 服务器监控与压测

- [ ] 服务器资产配置与密码保存策略可独立设置，公开 API 不返回密码或密文。
- [ ] SSH 会话可连接、采样、心跳、显式关闭，并在空闲后自动回收。
- [ ] `nvidia-smi` 可用时展示 GPU 指标；`gpu-burn` 不可用时不影响基础监控。
- [ ] GPU 繁忙时允许监控，但满载压测按安全策略阻止。
- [ ] 压测结束后可下载独立 DOCX/PDF 报告。

## 7. 安全验收边界

- 生产环境必须由环境变量或密钥管理系统提供 `LIEMA_MASTER_KEY`，并保证升级/恢复前后使用同一密钥。
- MySQL 必须使用平台专用数据库或 schema，不得连接后修改业务原始数据库。
- MinIO 必须使用平台专用 bucket 或严格隔离的 prefix。
- Redis 仅作为任务唤醒和心跳组件，禁止公网暴露；生产环境必须启用认证，优先使用独立 ACL 用户。
- Web 仅限受控局域网时可使用 HTTP，并设置 `LIEMA_SESSION_COOKIE_SECURE=false`、限制允许访问的网段；入口使用 HTTPS 时必须改为 `true`。不得把 HTTP 入口暴露公网。
- 平台不会自动升级驱动、CUDA、内核或容器运行时，也不会自动停止业务容器。
- GPU 满载验收必须有维护窗口、明确目标卡并确认业务负载已释放。
