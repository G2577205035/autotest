# 第 4 工作日：服务器兼容性闭环

## 今日完成

- 兼容性预检新增 SSH 自定义端口，以及连接超时、认证失败、地址解析失败等明确提示。
- 新增操作系统版本、CPU 架构、内存、`/tmp` 权限与空间、cgroup、glibc、后台执行工具检查。
- CPU 压测可在 `stress-ng` 与 Python 降级引擎之间选择；缺少必要条件时直接阻断并列出处理建议。
- GPU 压测继续以 `nvidia-smi` 和 `gpu-burn` 为核心，DCGM 仅作为可选诊断；源码构建前检查 `nvcc`、`make`、`g++` 和临时空间。
- 新增 `gpu-burn` 容器执行器：目标机无需安装宿主机 CUDA/nvcc，只需具备 NVIDIA 容器运行时和平台验证镜像。
- 新增 GPU 业务负载保护：显存占用或利用率超过安全阈值时默认阻止烧卡，避免压测干扰在线业务。
- 页面支持指定单张或多张 GPU；只检查并运行所选卡，便于在业务节点上分批释放、分批验证。
- GPU 兼容策略从固定 `sm_86` 升级为 compute capability 自动识别；CUDA 11.8 通用镜像覆盖 Turing/Ampere/Ada，Blackwell 优先 CUDA 12.8 原生镜像。
- 页面只展示本次所选模式的结论，并补充兼容级别、账号权限、内存、临时空间和缺失项。
- 修复 MinIO 运行目录被当成本地路径处理导致企业报告缺图的问题，受影响报告已重新生成并恢复图表。
- 修复 PyCharm 虚拟环境失效问题，项目依赖和启动检查均通过。

## 验证结果

- 自动化测试：62 项全部通过。
- 应用健康检查：MySQL、MinIO 后端均正常。
- 报告校验：快照、DOCX 关系及文件内部均包含 9 张图表，11 页渲染检查通过。

## 真实环境验证

已在 openEuler 24.03 LTS-SP3、8 张 RTX 3090 的真实节点完成验证。CUDA 11.8 / sm_86 独立镜像构建成功，无压枚举识别全部 8 张卡，前后显存占用未增加；节点当前仍承载在线 GPU 业务，因此正式烧卡必须等维护窗口或释放后的空闲 GPU。
