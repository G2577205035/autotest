# 烈马自动化测试平台灾备与镜像回滚演练记录

> 演练日期：2026-08-24  
> 演练编号：`20260824-164909`  
> 适用版本：`auto-test 2.0.0`  
> 结果：平台专用数据的同机隔离恢复与镜像回滚通过；离机副本和 Redis 认证仍待运维资源。

## 1. 范围与安全边界

- 只操作平台专用 MySQL 数据库、MinIO 前缀和 5 个 Compose 持久卷，没有修改业务原始数据库、共享 MinIO 其他前缀或共享 Redis 配置。
- 开始前确认业务自动化、报告、接口场景和压测四类持久化任务均无排队或运行任务，最近 10 分钟无审计活动。
- 生产环境文件保持 `0600`，备份根目录保持 `0700`；记录中不保存主机地址、数据库名、bucket 名或明文凭据。
- 临时恢复数据库、MinIO 验证前缀和 Docker 卷均使用本次演练唯一编号，验证后检查为零并完成清理。

## 3. MinIO 枚举差异与处置

首次使用服务器 `mc mirror` 时命令返回成功，但只保存了 18 个对象、约 2.5 MB；生产容器网络路径中的同版本 Python 客户端也只枚举到 18 个对象。工作站从平台当前配置的存储入口只读枚举得到 539 个实际文件、41,839,140 字节。

本次没有把“命令成功”误判为备份成功，最终改为：

1. 使用能完整枚举 539 个对象的客户端读取平台专用前缀。
2. 通过 SFTP 加密通道直接写入服务器受限备份目录，不在工作站落生产文件。
3. 对 539 个对象逐个记录大小和 SHA-256，随后完成隔离恢复和逐对象回读。
4. 保留两次不完整枚举证据，供后续排查服务器侧网络路径或对象存储兼容性。

因此，后续 MinIO 备份必须以“应用侧源清单数量/字节数 + 备份清单 + 恢复回读哈希”三方一致为完成条件。

## 5. 镜像回滚演练

演练前发现 Web、Worker 正在运行的无标签镜像与已重建的固定标签存在漂移。为避免丢失容器内已完成的受控修补，先通过 `docker export | docker import` 分别生成不包含 Compose 环境变量的 Web/Worker 基线快照，再执行：

1. 从原运行态启动并完成烟雾检查。
2. 前滚到固定镜像 `sha256:4601afb81f06eaaeff287cef1165b722ad985bcb79d3827826c777fbc8236550`。
3. 回滚到 Web/Worker 各自的运行态基线快照。
4. 再次前滚到固定镜像，并作为最终生产状态。

三次切换及原运行态均满足：

- `/health` 为 `ok`，Redis 可用且 Worker 心跳在线。
- 首页 200、认证状态 200 且 `Cache-Control: no-store`、匿名业务接口 401。
- Web/Worker 可导入 `auto_test`，图表依赖 `packaging` 可用。
- 最终 Web/Worker 镜像 ID 均与固定标签一致。
- 最近 10 分钟 Web/Worker 日志未发现 Traceback、ERROR 或未处理异常。

基线快照和回滚 override 保留在服务器，并与本次备份编号关联。
